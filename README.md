# VenueBooking API

Цей проєкт створено для виконання тестового завдання, метою якого є розробка REST API
для управління залами, бронюваннями та розрахунку вартості оренди з урахуванням часу доби.

API дозволяє вести каталог залів і додаткових послуг, шукати вільні зали за датою,
часовим проміжком і місткістю, а також оформлювати бронювання з автоматичним розрахунком
вартості. Оренда рахується посегментно за правилами ціноутворення, до неї додається вартість обраних послуг, зафіксована на момент
бронювання.

У проєкті передбачено окремий блок для звітів та аналітики. Загалом представлено 5 різновидів:

| Звіт | Призначення |
|------|-------------|
| `Venue Popularity`   | рейтинг залів за кількістю бронювань |
| `Service Popularity` | рейтинг послуг за кількістю замовлень |
| `Hour Demand`        | заброньований час у розрізі годин доби |
| `Revenue`            | виручка сумарно та по залах |
| `Occupancy`          | завантаженість залів — заброньовані години проти доступних |

Додаткові особливості:

- **Документація** — OpenAPI-специфікація та Swagger UI.
- **Ендпоінти** — усі ендпоінти створені з використанням Minimal API.
- **Обробка помилок** — усі помилки повертаються у форматі `ProblemDetails`
- **Початкові дані** — база автоматично наповнюється почтковими даними при першому старті.
- **Контейнеризація** — запуск проєкту можна здійснити однією командою через Docker Compose.

## Швидкий старт

### Docker Compose

Для запуску потрібен Docker Desktop.

1. Клонувати репозиторій і перейти в папку проєкту:

   ```bash
   git clone https://github.com/Nazg0r/TZ-VenueBooking.git
   cd TZ-VenueBooking
   ```

2. Запустити збірку та контейнери:

   ```bash
   docker compose up --build
   ```

   Compose піднімить PostgreSQL, дочекається її готовності, далі збере
   й запустить API. Міграції та початкові дані застосуються автоматично під час старту застосунку.

3. Відкрити документацію:

   - Swagger UI — <http://localhost:8080/swagger>
   - OpenAPI-документ — <http://localhost:8080/openapi/v1.json>

   PostgreSQL при цьому доступна на `localhost:5433` (база `venuebookingdb`,
   користувач / пароль — `postgres` / `postgres`).

Зупинити: `docker compose down`.

### Локальний запуск

Потрібні встановлені .NET 10 SDK та запущений екземпляр PostgreSQL.

1. Клонувати репозиторій і перейти в його теку.

   ```bash
   git clone https://github.com/Nazg0r/TZ-VenueBooking.git
   cd TZ-VenueBooking
   ```

2. Створити файл `VenueBooking.Api/appsettings.Development.json` з рядком підключення
   до PostgreSQL (див. розділ [«Конфігурація»](#конфігурація)).

3. Запустити API:

   ```bash
   dotnet run -p VenueBooking.Api
   ```

4. Відкрити <https://localhost:5001/swagger>.

Створювати базу, застосовувати міграції чи виконувати наповнення вручну не потрібно — усе
здійснюється при старті застосунку.

## Конфігурація

Файли `appsettings.json` та `appsettings.Development.json` виключені з репозиторію, тому **для запуску без Docker їх потрібно створити вручну**.

Мінімальний `VenueBooking.Api/appsettings.Development.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Port=5432;Database=venuebookingdb;Username=postgres;Password=postgres"
  }
}
```

Значення `Server`, `Port`, `Database`, `Username`, `Password` потрібно замінити на
параметри вашого екземпляра PostgreSQL.

Рядок підключення також можна передати через змінну середовища (має пріоритет над файлом):

```
ConnectionStrings__DefaultConnection=Host=localhost;Port=5432;Database=venuebookingdb;Username=postgres;Password=postgres
```

Якщо рядок підключення не заданий, застосунок завершується з помилкою
`Connection string 'DefaultConnection' is not configured.`

У Docker-варіанті рядок підключення вже прописаний у `docker-compose.yml`
і вказує на сервіс бази `venuebooking.db` — додаткова конфігурація не потрібна.

## Архітектура

Рішення розділене на чотири проєкти за принципом багатошарової архітектури.
Усі залежності спрямовані до домену, який не залежить ні від чого.

```
VenueBooking.Api  ──►  VenueBooking.BusinessLogic  ──►  VenueBooking.Domain
       │          ──►  VenueBooking.DataAccess      ──►  VenueBooking.Domain
```

- **VenueBooking.Domain** — моделі (`Venue`, `Booking`, `BookingItem`, `Service`,
  `PricingRule`), доменна логіка розрахунку оренди,
  контракти, інтерфейси репозиторіїв і сервісів, спільні типи.
- **VenueBooking.DataAccess** — `DbContext`, конфігурація EF Core, міграції,
  реалізації репозиторіїв, ініціалізація та початкове наповнення бази.
- **VenueBooking.BusinessLogic** — сервіси застосунку (`VenueService`, `BookingService`,
  `ReportService` тощо).
- **VenueBooking.Api** — ASP.NET Core Minimal API. Включає групи ендпоінтів, DTO запитів і
  відповідей, мапінги, розширення.

## База даних

- **СКБД:** PostgreSQL, доступ через EF Core (провайдер Npgsql).
- **Міграції** застосовуються автоматично при старті застосунку.
- **Початкові дані** заповнюються одразу після міграцій.

Демонстраційні дані, що створюються при першому старті:

| Категорія | Вміст |
|-----------|-------|
| Послуги | Проєктор — 500, Wi-Fi — 300, Звук — 700 |
| Правила ціноутворення | Стандартні `09:00–18:00` ×1.00 · Ранкові `06:00–09:00` ×0.90 · Вечірні `18:00–23:00` ×0.80 · Пікові `12:00–14:00` ×1.15 (підвищений пріоритет) |
| Зали | Зал A — 50 місць, 2000/год (Проєктор, Wi-Fi) · Зал B — 100 місць, 3500/год (усі послуги) · Зал C — 30 місць, 1500/год (Wi-Fi) |

## Підсумок

Реалізація покриває всі вимоги технічного завдання:

- управління залами — створення, редагування, видалення;
- пошук вільних залів за датою, часовим проміжком і місткістю;
- бронювання з розрахунком вартості оренди залежно від часу доби та вартості додаткових послуг;
- звіти й аналітика;
- документація OpenAPI / Swagger;
- (додатково) контейнеризація з автоматичними міграціями та початковими даними.
